How I Reduced the Execution Time of My Mail Extractor

By Bhavesh Bhagoria · July 22, 2026

1. Same-domain filtering

While crawling through a website, the crawler could pick up links to external sites such as Wikipedia, etc., which would affect the execution time — and could also give wrong output. I used Python's urllib.parse.urlparse: 

from urllib.parse import urlparse

def is_same_domain(base_url, target_url):
    return urlparse(base_url).netloc == urlparse(target_url).netloc

urlparse splits a URL into pieces — scheme, netloc (hostname), path, etc. I compared the netloc of the current URL, before putting it in the queue, with the target domain (of the link provided by the user). This solved a small-looking problem, but it improved the efficiency significantly by stopping the crawler from working unnecessarily.

2. Using asyncio and aiohttp

In I/O-bound operations like this, execution time is high due to waiting on network responses. This time can be saved if we handle network responses asynchronously. While performing asynchronous tasks, we cannot use requests to handle network responses, because it uses blocking sockets — and for asynchronous tasks we need non-blocking sockets instead. I also used a single aiohttp.ClientSession() for every request, which saved time on DNS lookups, TCP handshakes, etc. (keep-alive).

3. Using 5 workers, asyncio.Lock(), and a set instead of a list

I used 5 workers to concurrently pull URLs from a single shared queue and crawl them asynchronously. To avoid duplicate work, I used two sets:

  • seen — checked when a new link is discovered on a page. Before queuing it, I check if it's already in seen, and if not, add it and queue it. This stops the same link from being queued twice if multiple pages link to it.
  • visited — checked when a worker pulls a URL off the queue, right before fetching it. This stops two workers from fetching the same page twice.

I used sets instead of lists for both, because workers need to run this "have I seen/visited this?" check on every single link throughout the crawl. A list would need to scan every existing entry (O(N), getting slower as it grows), whereas a set answers the same check in roughly constant time (O(1)), using hashing to jump straight to where the item would be instead of scanning.
